# UI + API 智能扫描 Phase 1 低保真布局

## 1. 布局目标

Phase 1 的低保真布局只解决信息组织和交互顺序，不定义最终视觉样式。

核心目标：
- 用户先填清楚范围，再生成计划。
- AI 输出先被解释，再进入确认。
- 禁止项、需确认项、条件允许项必须分层展示。
- 不出现“开始执行”按钮。

### 2.7 创建页按钮规则

| 按钮 | 启用条件 | 行为 |
|---|---|---|
| 取消 | 始终可用 | 返回列表，不保存 |
| 保存草稿 | 基础信息完整 | 保存 Campaign draft，不生成计划 |
| 生成测试计划 | URL、范围、allowed_domains、allowed_paths 完整 | 调用 generate-plan，只生成计划 |

创建页禁止出现：
- 开始执行。
- 一键扫描。
- 立即运行。

### 4.2 禁止项规则

禁止项展示为只读卡片：

```text
┌─ 禁止项 ────────────────────────────────────────────────┐
│ DELETE /api/users/{id}                                  │
│ 原因：用户明确排除删除用户，且删除动作默认禁止。           │
│ 处理：不会生成可执行 step。                               │
│ 可选操作：[返回修改 Campaign]                             │
└─────────────────────────────────────────────────────────┘
```

禁止项不能出现：
- 允许执行。
- 确认执行。
- 强制执行。

### 4.3 条件允许项规则

```text
┌─ 条件允许项 ────────────────────────────────────────────┐
│ POST /api/payments/mock                                 │
│ 条件：                                                   │
│ ✓ 环境非生产：sandbox                                    │
│ ✗ provider 为 mock：未检测到 provider 标记                │
│ ✓ 禁止真实支付：已配置                                    │
│                                                         │
│ 状态：条件未全部满足，只能生成计划，不生成可执行 step。      │
└─────────────────────────────────────────────────────────┘
```

### 4.4 底部操作规则

| 按钮 | Phase 1 是否出现 | 行为 |
|---|---|---|
| 返回计划 | 是 | 回到 AI 计划预览页 |
| 保存确认草稿 | 是 | 保存用户选择 |
| 生成资产草稿 | 是 | 生成 API/UI draft，不执行 |
| 开始执行 | 否 | Phase 1 禁止出现 |

## 5. 状态流转

```text
Campaign draft
  -> generate-plan
Plan generated
  -> user review
Review saved
  -> generate asset drafts
Asset drafts generated

禁止：
Asset drafts generated -> execution
```

## 6. 低保真验收标准

- 用户能在创建页明确看到“不会自动执行”。
- 创建页字段覆盖 Phase 0 模板。
- 计划预览页能解释 UI/API 候选来源和匹配原因。
- 风险与拦截区能同时展示禁止、需确认、条件允许。
- 执行前确认页不出现开始执行按钮。
- 禁止项没有任何允许执行入口。
- 条件允许项必须展示条件是否满足。
