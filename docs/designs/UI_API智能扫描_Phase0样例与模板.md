# UI + API 智能扫描 Phase 0 样例与模板

## 1. Phase 0 目标

Phase 0 不做完整执行功能，目标是验证用户能否用自然语言稳定描述测试范围，并让 AI 生成可读、可确认、可审计的测试计划。

验收重点：
- 用户输入是否足够清晰。
- AI 是否能识别模块边界。
- AI 是否能区分可执行动作和危险动作。
- 输出计划是否能被 QA / 开发 / 产品共同评审。

## 2. 用户输入模板

### 2.1 最小模板

```text
目标 URL：
测试范围：
测试模式：黑盒 / 灰盒 / 白盒
测试强度：Smoke / Regression / Deep
禁止动作：
补充说明：
```

### 2.2 推荐模板

```text
目标 URL：https://staging.example.com
业务模块：用户管理
测试范围：登录、用户列表、新建用户、编辑用户信息
不测试范围：删除用户、重置密码、发送邀请短信
测试模式：灰盒
测试强度：Smoke
允许域名：staging.example.com
允许路径：/login, /users, /api/users
禁止动作：delete, send_sms, send_email, payment
需确认动作：POST /api/users
条件允许动作：仅允许写入 test_user_* 测试数据
测试账号：使用环境变量中的默认测试账号
环境安全标记：staging
数据写入策略：允许测试数据写入，执行后人工清理
期望输出：先生成测试计划，不自动执行
```

### 2.3 强约束模板

```text
目标 URL：
业务模块：
必须覆盖：
明确不覆盖：
允许域名：
允许路径：
测试模式：黑盒 / 灰盒 / 白盒
测试强度：Smoke / Regression / Deep

动作策略：
- 禁止动作：永不自动执行，例如真实支付、删除生产数据、发送短信。
- 需确认动作：生成计划但执行前逐步确认，例如 POST/PUT/PATCH/DELETE、表单提交、导出、上传。
- 条件允许动作：满足环境、数据和清理条件后可执行，例如沙箱支付、测试商品购物车操作。

数据与环境：
- 环境安全标记：sandbox / staging / production-readonly
- 数据写入策略：禁止写入 / 允许测试数据写入 / 仅沙箱写入
- 测试数据标识：例如 test_user_*、test_product_id=xxx
- 清理策略：无需清理 / 自动清理 / 人工清理
- 是否允许表单提交：否 / 需要确认 / 是
- 是否允许 POST/PUT/PATCH/DELETE：否 / 需要确认 / 是

特殊动作限制：
- 文件上传限制：允许类型、最大大小、测试文件目录
- 导出限制：最大行数、允许字段、是否允许下载落盘
- 支付限制：仅 mock / sandbox provider，禁止真实渠道

输出格式：测试计划 / 资产草稿 / 执行前检查表
```

## 3. 10 个真实/半真实业务模块样例

| 编号 | 模块 | 用户输入示例 | 推荐模式 | 默认强度 | 主要风险 |
|---|---|---|---|---|---|
| S01 | 登录 | 测登录页，覆盖正常登录、错误密码、空用户名，不测试注册和找回密码 | 黑盒 | Smoke | 登录失败重试过多触发风控 |
| S02 | 用户管理 | 测用户列表和新建用户，不测试删除、重置密码、发邀请短信 | 灰盒 | Smoke | 写入用户数据、发送消息 |
| S03 | 订单查询 | 测订单列表、订单详情、筛选条件，不测试取消订单和退款 | 灰盒 | Regression | 误触发取消/退款 |
| S04 | 商品目录 | 测商品列表、搜索、分类、详情页，不测试上下架和改价 | 黑盒 | Regression | 修改商品状态或价格 |
| S05 | 购物车 | 测加入购物车、修改数量、移除测试商品，不进入真实支付 | 灰盒 | Smoke | 生成真实订单或库存锁定 |
| S06 | 支付 Mock | 只测沙箱支付和 mock 回调，不触发真实支付渠道 | 灰盒 | Regression | 真实扣款 |
| S07 | 文件上传 | 测头像上传和格式校验，只使用测试图片，不上传敏感文件 | 黑盒 | Smoke | 上传恶意或敏感文件 |
| S08 | 报表导出 | 测筛选和导出按钮，只导出测试范围内数据 | 灰盒 | Smoke | 导出敏感数据 |
| S09 | 权限设置 | 只生成权限页面测试计划，不执行保存和授权变更 | 白盒 | Smoke | 权限变更影响账号 |
| S10 | 审批流 | 测审批列表和详情，不执行同意、拒绝、撤回 | 灰盒 | Smoke | 改变业务流程状态 |

## 4. 动作策略词表初版

### 4.1 策略分层

| 策略 | 含义 | 执行规则 |
|---|---|---|
| 禁止 | 风险不可接受或超出智能扫描定位 | 不生成可执行 step，只在计划中列为不执行项 |
| 需确认 | 有业务价值但可能写入、导出、上传或改变状态 | 生成 draft step，执行前必须逐步确认 |
| 条件允许 | 满足环境、数据、清理和范围约束后可执行 | 生成可执行候选，但必须展示满足的条件 |

### 4.2 高危业务动作

| 动作类别 | 中文关键词 | 英文关键词 | 默认策略 | 条件允许示例 |
|---|---|---|---|---|
| 删除 | 删除、移除、清空、注销、销毁 | delete, remove, clear, destroy, revoke | 禁止 | 仅允许删除本 Campaign 创建的 test_* 临时数据，且有清理记录 |
| 真实支付 | 支付、扣款、充值、提现、退款 | pay, charge, recharge, withdraw, refund | 禁止 | 无，真实资金动作不进入智能扫描 |
| 沙箱支付 | 沙箱支付、mock 支付、支付回调 | mock payment, sandbox payment, callback | 条件允许 | 环境标记为 sandbox/mock，provider 明确非真实渠道 |
| 消息发送 | 发送短信、发送邮件、通知、邀请 | send_sms, send_email, notify, invite | 禁止 | 仅允许 mock provider 或本地捕获邮箱/短信服务 |
| 权限变更 | 授权、提权、降权、分配角色 | grant, revoke, role, permission | 禁止 | Phase 0 只生成计划，不生成执行 step |
| 状态流转 | 审批、拒绝、撤回、取消订单 | approve, reject, withdraw, cancel | 需确认 | 仅测试沙箱流程或测试单据，且可回滚 |
| 数据导出 | 导出、下载报表、下载数据 | export, download, dump | 需确认 | 限制最大行数、字段白名单、测试数据范围，不落盘或落临时目录 |
| 文件上传 | 上传、导入、批量导入 | upload, import, bulk_import | 需确认 | 限制文件类型、大小、测试文件目录，禁止可执行文件和敏感文件 |
| 数据写入 | 新建、编辑、保存、提交 | create, update, save, submit | 需确认 | 仅写入 test_* 数据，明确清理策略和环境非生产 |

### 4.3 技术风险动作

| 动作类别 | 关键词 | 默认策略 | 处理方式 |
|---|---|---|---|
| 压力测试 | 压测、并发、轰炸、stress、load、flood | 禁止 | 转 Turbo 专用流程，不进入智能扫描 |
| 越权探测 | 绕过、提权、越权、bypass、privilege escalation | 禁止 | 只允许授权安全测试计划，不自动执行 |
| 注入类 payload | SQL 注入、XSS、命令注入、SSRF | 禁止 | 只允许安全评审计划，不进入默认扫描 |
| 爬虫扩散 | 全站扫描、全域扫描、无限爬取 | 需确认 | 必须设置最大页面数、最大接口数和路径 scope |
| 跨域访问 | 外部域名、第三方域名 | 需确认 | 必须命中 allowed_domains |
| 文件系统访问 | 本地文件、下载目录、上传目录 | 需确认 | 只能使用配置的测试目录 |

## 5. AI 输出测试计划样例

### 5.1 用户输入

```text
目标 URL：https://staging.example.com
业务模块：用户管理
测试范围：登录、用户列表、新建用户
不测试范围：删除用户、重置密码、发送邀请短信
测试模式：灰盒
测试强度：Smoke
期望输出：先生成测试计划，不自动执行
```

### 5.2 测试计划输出

```text
Campaign：用户管理模块 Smoke 灰盒扫描
状态：Draft，未执行

范围确认：
- 包含：登录、用户列表、新建用户
- 排除：删除用户、重置密码、发送邀请短信
- 允许路径：/login, /users, /api/users
- 禁止动作：delete, reset_password, send_invitation

UI 流程候选：
1. 打开登录页
2. 输入测试账号和密码
3. 点击登录
4. 进入用户管理页面
5. 搜索用户列表
6. 打开新建用户弹窗
7. 填写测试用户信息
8. 提交前停在确认点，等待人工确认是否执行写入

API 候选：
1. POST /api/auth/login
2. GET /api/users
3. POST /api/users（需要人工确认）

风险项：
- POST /api/users 会写入用户数据，需要确认测试环境和清理策略。
- 页面可能存在“删除用户”按钮，默认不点击。
- 如果登录失败重试超过 3 次，停止执行，避免触发风控。

建议断言：
- 登录成功后 URL 或页面标题变化。
- 用户列表接口返回 200。
- 用户列表包含 data/items 数组。
- 新建用户接口如执行，应返回 200/201，并返回用户 ID。

不执行项：
- 删除用户。
- 重置密码。
- 发送邀请短信。
```

## 6. Campaign 报告样例

```text
Campaign：用户管理模块 Smoke 灰盒扫描
执行状态：计划已生成，未执行

范围覆盖：
- 已覆盖计划：登录、用户列表、新建用户
- 未覆盖：删除用户、重置密码、邀请短信
- 超出范围并已拦截：删除用户

资产草稿：
- API Case 草稿：3 个 steps
- UI Case 草稿：1 条主流程
- 需要人工确认的步骤：1 个 POST /api/users

风险摘要：
- 高风险：无确认写操作，已阻止
- 中风险：新建用户可能产生测试数据
- 低风险：登录失败可能触发风控，已限制重试次数

人工复核项：
1. 是否允许执行 POST /api/users。
2. 新建用户后是否需要清理测试数据。
3. 是否需要补充“编辑用户信息”回归路径。

下一步建议：
- 如果确认允许写入测试数据，进入 Phase 2 生成 API Case IR v2 和 Visual UI Case。
- 如果不允许写入，只保留登录和用户列表的只读测试。
```

## 8. Phase 0 退出标准

Phase 0 通过前，不进入 Campaign 页面和后端接口开发。

退出标准：
- 至少 10 个样例都能生成测试计划。
- 至少 8 个样例的计划被人工评审为“可读、可确认”。
- 100% 高危动作被识别并进入禁止或确认流程。
- 每个计划都能说明：范围、风险、候选 UI 步骤、候选 API 步骤、不执行项。
- 至少 3 个样例能明确映射到现有 API Asset 或 Test Case。
