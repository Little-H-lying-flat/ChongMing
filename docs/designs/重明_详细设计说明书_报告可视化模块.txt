1. 系统概述 (System Overview)

1.1 定义与愿景

报告可视化模块 (Report Visualization Module) 是重明架构中负责 "呈" (Present) 和 "析" (Analyze) 的输出组件。它将测试执行结果转化为直观、美观、可交互的报告，帮助团队快速定位问题。

其核心设计哲学是 "Data-Driven, Visual-First" (数据驱动，视觉优先)：
- 一目了然：通过图表和颜色编码，快速识别测试健康度
- 深度钻取：支持从总览到详情的逐层下钻
- 历史对比：支持跨时间维度的趋势分析

1.2 核心职责
- 数据聚合 (Data Aggregation)：收集各引擎执行结果，统一数据格式
- 可视化渲染 (Visualization Rendering)：生成图表、时间线、截图对比
- 报告生成 (Report Generation)：支持 HTML、PDF、Allure 格式输出
- 趋势分析 (Trend Analysis)：历史数据分析，识别质量趋势

4. Allure 集成方案

4.1 数据适配器

重明执行日志转换为 Allure 标准格式：

class AllureAdapter:
    def convert_tc_result(self, result: TestCaseResult) -> dict:
        return {
            "uuid": result.tc_id,
            "historyId": self._generate_history_id(result),
            "name": result.name,
            "status": self._map_status(result.status),
            "stage": "finished",
            "start": self._to_timestamp(result.started_at),
            "stop": self._to_timestamp(result.ended_at),
            "steps": [
                self._convert_step(step) for step in result.steps
            ],
            "attachments": self._collect_attachments(result),
            "labels": [
                {"name": "engine", "value": result.engine},
                {"name": "suite", "value": result.suite_name}
            ]
        }
    
    def _convert_step(self, step) -> dict:
        return {
            "name": f"{step.action}: {step.target}",
            "status": self._map_status(step.status),
            "start": step.started_at,
            "stop": step.ended_at,
            "attachments": [
                {"name": "screenshot", "source": step.screenshot, "type": "image/png"}
            ] if step.screenshot else []
        }

4.2 生成流程

1. 执行完成后，TraceLog 写入 JSON
2. AllureAdapter 转换为 Allure 格式
3. 写入 allure-results 目录
4. 调用 allure generate 生成 HTML 报告

generate_allure_report():
    # 1. 转换数据
    for tc in test_results:
        allure_data = adapter.convert_tc_result(tc)
        write_json(f"allure-results/{tc.id}-result.json", allure_data)
    
    # 2. 生成报告
    subprocess.run(["allure", "generate", "allure-results", "-o", "allure-report"])

6. API 接口设计

6.1 报告查询接口

GET /api/v1/reports
- 参数: page, limit, date_from, date_to
- 返回: 报告列表

GET /api/v1/reports/{run_id}
- 返回: 单次执行详情

GET /api/v1/reports/{run_id}/cases/{tc_id}
- 返回: 用例执行详情（含截图、日志）

GET /api/v1/trends
- 参数: period (7d, 30d, 90d)
- 返回: 趋势数据

6.2 报告导出接口

POST /api/v1/reports/{run_id}/export
- 参数: format (html, pdf, allure)
- 返回: 下载链接

7. 数据存储

7.1 数据库选型
- 结构化数据: PostgreSQL (报告元数据、统计)
- 文件存储: 本地文件系统 / MinIO (截图、视频、日志)

7.2 数据表设计

CREATE TABLE test_runs (
    id VARCHAR(50) PRIMARY KEY,
    started_at TIMESTAMP,
    ended_at TIMESTAMP,
    status VARCHAR(20),
    total_cases INT,
    passed_cases INT,
    failed_cases INT,
    skipped_cases INT,
    pass_rate DECIMAL(5,2)
);

CREATE TABLE test_case_results (
    id SERIAL PRIMARY KEY,
    run_id VARCHAR(50) REFERENCES test_runs(id),
    tc_id VARCHAR(100),
    name VARCHAR(200),
    engine VARCHAR(20),
    status VARCHAR(20),
    duration_ms INT,
    error_message TEXT,
    trace_log_path VARCHAR(500),
    video_path VARCHAR(500)
);

CREATE TABLE test_step_results (
    id SERIAL PRIMARY KEY,
    tc_result_id INT REFERENCES test_case_results(id),
    step_id INT,
    action VARCHAR(50),
    status VARCHAR(20),
    duration_ms INT,
    screenshot_path VARCHAR(500),
    error_detail TEXT
);
