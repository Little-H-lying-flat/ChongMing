# UI + API 智能扫描 Phase 0 计划质量评审

## 1. 评审目的

本评审不验证代码实现，而验证“自然语言 + URL + 模块范围”是否能稳定产出可读、可确认、可审计的 UI + API 测试计划。

Phase 0 通过后，才允许进入 Campaign 页面和后端接口设计。

## 2. 评审方法

基于 `UI_API智能扫描_Phase0样例与模板.md` 中的 10 个业务样例，对每个样例模拟生成测试计划，并按以下维度评审：

| 维度 | 通过标准 |
|---|---|
| 范围清晰 | 能明确包含和排除哪些模块 |
| 安全边界 | 高危动作能被识别并进入禁止或确认流程 |
| UI 计划 | 能生成可理解的 UI 路径或页面检查点 |
| API 计划 | 能生成候选 API 探测点或资产匹配方向 |
| 可复用资产 | 能映射到 API Case / UI Case / Campaign |
| 人工复核 | 能列出需要用户确认的动作 |

评分：
- 通过：该样例可进入 Phase 1 计划生成验证。
- 部分通过：需要补充模板或禁止词。
- 不通过：自然语言范围不足或风险不可控。

## 3. 样例评审结果

### S01 登录模块

用户输入：

```text
测登录页，覆盖正常登录、错误密码、空用户名，不测试注册和找回密码。
```

生成计划摘要：
- UI 路径：打开登录页 -> 输入正确账号密码 -> 提交 -> 验证进入首页；再覆盖错误密码、空用户名校验。
- API 候选：POST /api/auth/login；可选 GET /api/me 或 GET /api/profile 验证登录态。
- 不执行项：注册、找回密码。
- 风险项：连续错误密码可能触发风控，应限制失败尝试次数。
- 资产沉淀：1 条 UI smoke case，1 条 API login case，1 个 Campaign draft。

评审：通过。

### S02 用户管理模块

用户输入：

```text
测用户列表和新建用户，不测试删除、重置密码、发邀请短信。
```

生成计划摘要：
- UI 路径：登录 -> 用户管理 -> 列表加载 -> 搜索/筛选 -> 打开新建用户弹窗 -> 填写测试用户。
- API 候选：GET /api/users，POST /api/users。
- 不执行项：DELETE /api/users/{id}，POST /api/users/{id}/reset-password，POST /api/users/{id}/invite。
- 风险项：POST /api/users 会写入测试数据，必须人工确认并要求清理策略。
- 资产沉淀：用户列表只读 API case，新建用户 API draft，UI draft。

评审：通过。

### S03 订单查询模块

用户输入：

```text
测订单列表、订单详情、筛选条件，不测试取消订单和退款。
```

生成计划摘要：
- UI 路径：进入订单列表 -> 按状态/时间筛选 -> 打开订单详情 -> 返回列表。
- API 候选：GET /api/orders，GET /api/orders/{id}。
- 不执行项：POST /api/orders/{id}/cancel，POST /api/refunds，PATCH /api/orders/{id}/status。
- 风险项：取消和退款属于状态流转/资金动作，默认禁止。
- 资产沉淀：订单查询 regression API case，订单详情 UI case。

评审：通过。

### S04 商品目录模块

用户输入：

```text
测商品列表、搜索、分类、详情页，不测试上下架和改价。
```

生成计划摘要：
- UI 路径：打开商品列表 -> 搜索关键词 -> 切换分类 -> 打开详情页。
- API 候选：GET /api/products，GET /api/products/{id}，GET /api/categories。
- 不执行项：PATCH /api/products/{id}/status，PATCH /api/products/{id}/price。
- 风险项：上下架和改价会影响业务展示，默认禁止。
- 资产沉淀：商品目录 UI case，商品查询 API case。

评审：通过。

### S05 购物车模块

用户输入：

```text
测加入购物车、修改数量、移除测试商品，不进入真实支付。
测试数据标识：test_product_id=xxx
数据写入策略：允许测试数据写入
清理策略：允许删除本 Campaign 创建的购物车测试数据
写操作确认：每步确认
```

生成计划摘要：
- UI 路径：商品详情 -> 加入购物车 -> 进入购物车 -> 修改数量 -> 移除测试商品。
- API 候选：POST /api/cart/items，PATCH /api/cart/items/{id}，DELETE /api/cart/items/{id}。
- 不执行项：进入结算、创建真实订单、支付。
- 条件允许项：仅允许操作 `test_product_id=xxx` 产生的购物车临时数据。
- 风险项：购物车写入和 DELETE 需要逐步确认，并记录清理结果。
- 资产沉淀：购物车 HYBRID draft。

复评：通过。

通过原因：补充测试商品 ID、数据写入策略和清理策略后，写操作边界清晰，DELETE 仅用于清理本 Campaign 创建的临时数据。

### S06 支付 Mock 模块

用户输入：

```text
只测沙箱支付和 mock 回调，不触发真实支付渠道。
环境安全标记：sandbox
支付限制：仅 mock / sandbox provider，禁止真实渠道
写操作确认：每步确认
```

生成计划摘要：
- UI 路径：订单页 -> 选择沙箱支付 -> 进入 mock 支付确认页 -> 验证回调结果。
- API 候选：POST /api/payments/mock，POST /api/payments/callback/mock，GET /api/payments/{id}。
- 不执行项：真实支付网关、真实扣款、提现、退款。
- 条件允许项：仅当环境标记为 `sandbox` 且 provider 明确为 mock/sandbox 时生成可执行候选。
- 风险项：若无法验证 sandbox/mock 标记，支付相关步骤只保留为计划，不生成执行 step。
- 资产沉淀：支付 mock API case，支付 UI smoke draft。

复评：通过。

通过原因：新增环境安全标记和支付 provider 约束后，真实资金动作被固定列为禁止，mock 支付在条件满足时可进入候选执行。

### S07 文件上传模块

用户输入：

```text
测头像上传和格式校验，只使用测试图片，不上传敏感文件。
文件上传限制：仅允许 png/jpg/webp，最大 2MB，测试文件目录为 test-assets/uploads/
写操作确认：每步确认
```

生成计划摘要：
- UI 路径：进入个人资料 -> 打开头像上传 -> 上传测试图片 -> 验证预览/保存提示 -> 上传非法格式验证错误提示。
- API 候选：POST /api/profile/avatar，GET /api/profile。
- 不执行项：批量导入、上传敏感文件、上传可执行文件、上传测试目录外文件。
- 条件允许项：仅允许上传 `test-assets/uploads/` 下的 png/jpg/webp 测试图片，且大小不超过 2MB。
- 风险项：上传动作需要确认文件路径、类型和大小；不读取用户本机任意文件。
- 资产沉淀：头像上传 UI case，上传 API draft。

复评：通过。

通过原因：补充文件类型、大小和测试文件目录后，上传范围可审计，不再依赖模糊的“测试图片”描述。

### S08 报表导出模块

用户输入：

```text
测筛选和导出按钮，只导出测试范围内数据。
导出限制：最大 100 行，只允许 order_id/status/created_at/amount_masked 字段，允许下载到临时目录，不允许全量导出。
写操作确认：每步确认
```

生成计划摘要：
- UI 路径：进入报表页 -> 设置筛选条件 -> 点击查询 -> 点击导出前进入确认点。
- API 候选：GET /api/reports，POST /api/reports/export 或 GET /api/reports/export。
- 不执行项：全量导出、敏感字段导出、超过 100 行导出、非临时目录落盘。
- 条件允许项：仅允许导出字段白名单内的测试范围数据，并限制最大 100 行。
- 风险项：导出动作必须展示字段白名单、行数限制和下载位置。
- 资产沉淀：报表查询 API case，导出动作 draft。

复评：通过。

通过原因：补充导出行数、字段白名单和落盘限制后，导出动作可被人工复核，敏感数据风险可控。

## 5. 发现的问题

### 5.1 写操作不是都应该禁止，但必须有数据策略

购物车、新建用户、文件上传这类测试有业务价值，但必须知道：
- 使用什么测试数据。
- 数据是否可清理。
- 是否仅限沙箱环境。
- 是否允许 DELETE 清理测试数据。

### 5.2 “Mock / Sandbox” 必须从环境配置中验证

支付 mock 不能只相信用户自然语言，必须有环境配置或 provider 标记证明当前不会触发真实渠道。

### 5.3 导出类动作需要数据治理字段

报表导出不是简单下载行为，必须额外确认：
- 数据范围。
- 敏感字段。
- 最大导出量。
- 是否允许落盘。

### 5.4 文件上传需要安全约束

上传类测试必须限制：
- 文件类型。
- 文件大小。
- 文件来源目录。
- 禁止可执行文件和敏感文件。

## 6. 输入模板修订建议

在推荐模板中增加：

```text
测试数据策略：无写入 / 允许测试数据写入 / 需要执行后清理
测试数据标识：例如 test_user_*, test_product_id=xxx
清理策略：无需清理 / 自动清理 / 人工清理
环境安全标记：sandbox / staging / production-readonly
文件上传限制：允许类型、最大大小、测试文件目录
导出限制：最大行数、允许字段、是否允许下载落盘
写操作确认：禁止 / 每步确认 / 本次允许
```
