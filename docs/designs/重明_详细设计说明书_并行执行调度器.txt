1. 系统概述 (System Overview)

1.1 定义与愿景

并行执行调度器 (Parallel Scheduler) 是重明架构中负责 "分" (Distribute) 和 "控" (Orchestrate) 的核心组件。它像交响乐指挥一样，协调多个测试用例的并行执行，最大化资源利用率。

其核心设计哲学是 "Dependency-Aware, Resource-Optimized" (依赖感知，资源优化)：
- 依赖分析：自动识别用例间的依赖关系，确保执行顺序正确
- 并行调度：无依赖的用例并行执行，提高效率
- 资源管理：动态分配浏览器实例和 Worker 资源
- 失败隔离：单用例失败不影响其他用例执行

1.2 核心职责
- 依赖图构建 (Dependency Graph)：分析 TC-IR 间的依赖关系
- 任务分片 (Task Sharding)：将用例集拆分为可并行的批次
- 资源池管理 (Resource Pool)：管理浏览器实例和执行器
- 执行编排 (Orchestration)：调度任务到 Worker 执行
- 结果聚合 (Result Aggregation)：收集并汇总执行结果

3. 依赖分析层 (Dependency Analysis)

3.1 依赖类型

| 依赖类型 | 描述 | 示例 |
|---------|------|------|
| 数据依赖 | 后续用例需要前序用例的输出数据 | 登录 → 获取 Token → 购买 |
| 顺序依赖 | 明确指定执行顺序 | setup → test → teardown |
| 资源依赖 | 共享同一资源，需互斥 | 多用例操作同一账号 |
| 无依赖 | 完全独立，可并行 | 不同功能模块的测试 |

3.2 依赖图构建

class DependencyAnalyzer:
    def build_dag(self, tc_list: list[TCIR]) -> nx.DiGraph:
        dag = nx.DiGraph()
        
        for tc in tc_list:
            dag.add_node(tc.id, tc=tc, status="pending")
            
            # 分析显式依赖
            for dep_id in tc.dependencies:
                dag.add_edge(dep_id, tc.id)
            
            # 分析隐式依赖（数据依赖）
            for var in tc.required_variables:
                provider = self._find_variable_provider(tc_list, var)
                if provider:
                    dag.add_edge(provider.id, tc.id)
        
        # 检测循环依赖
        if not nx.is_directed_acyclic_graph(dag):
            cycles = nx.find_cycle(dag)
            raise CircularDependencyError(cycles)
        
        return dag

3.3 拓扑排序与批次划分

def generate_batches(self, dag: nx.DiGraph) -> list[Batch]:
    batches = []
    remaining = set(dag.nodes())
    
    while remaining:
        # 找出所有入度为 0 的节点（无依赖或依赖已完成）
        ready = [n for n in remaining 
                 if all(pred not in remaining for pred in dag.predecessors(n))]
        
        if not ready:
            raise DeadlockError("存在无法解决的依赖")
        
        # 这些节点可以并行执行
        batches.append(Batch(
            id=len(batches) + 1,
            tasks=ready,
            parallel=True
        ))
        
        remaining -= set(ready)
    
    return batches

4. 调度层 (Dispatcher Layer)

4.1 任务队列

class TaskQueue:
    def __init__(self):
        self.queue = asyncio.PriorityQueue()
    
    async def enqueue(self, task: Task, priority: int = 0):
        # 优先级：0=最高，数字越大优先级越低
        await self.queue.put((priority, task))
    
    async def dequeue(self) -> Task:
        _, task = await self.queue.get()
        return task

4.2 负载均衡策略

| 策略 | 描述 | 适用场景 |
|------|------|---------|
| Round Robin | 轮询分配 | Worker 能力均等 |
| Least Connections | 最少任务优先 | 任务耗时差异大 |
| Resource Affinity | 资源亲和 | 特定 Worker 绑定特定资源 |
| Priority-Based | 优先级调度 | P0 用例优先执行 |

class LoadBalancer:
    def __init__(self, strategy: str = "least_connections"):
        self.strategy = strategy
        self.workers = []
    
    def select_worker(self, task: Task) -> Worker:
        if self.strategy == "least_connections":
            return min(self.workers, key=lambda w: w.current_tasks)
        elif self.strategy == "round_robin":
            return self.workers[self._rr_index % len(self.workers)]
        elif self.strategy == "resource_affinity":
            return self._find_affinity_worker(task)

4.3 Worker 管理

class WorkerPool:
    def __init__(self, size: int, browser_pool: BrowserPool):
        self.workers = [Worker(id=i, browser_pool=browser_pool) for i in range(size)]
    
    async def scale_up(self, count: int):
        """动态扩容"""
        for i in range(count):
            self.workers.append(Worker(id=len(self.workers)))
    
    async def scale_down(self, count: int):
        """动态缩容"""
        idle_workers = [w for w in self.workers if w.is_idle]
        for worker in idle_workers[:count]:
            await worker.shutdown()
            self.workers.remove(worker)

5. 资源池管理 (Resource Pool)

5.1 浏览器实例池

class BrowserPool:
    def __init__(self, max_instances: int = 10):
        self.max_instances = max_instances
        self.instances = []
        self.available = asyncio.Queue()
    
    async def acquire(self) -> BrowserContext:
        """获取浏览器实例"""
        if not self.available.empty():
            return await self.available.get()
        
        if len(self.instances) < self.max_instances:
            browser = await self._create_browser()
            self.instances.append(browser)
            return browser
        
        # 等待可用实例
        return await self.available.get()
    
    async def release(self, browser: BrowserContext):
        """归还浏览器实例"""
        await browser.clear_cookies()
        await browser.clear_storage()
        await self.available.put(browser)

5.2 实例复用策略

| 策略 | 描述 | 优势 |
|------|------|------|
| 复用 + 清理 | 清理 Cookie/Storage 后复用 | 启动快 |
| 每次新建 | 每个用例新建实例 | 完全隔离 |
| 按套件复用 | 同一测试套件内复用 | 平衡性能与隔离 |

6. 执行编排 (Orchestration)

6.1 编排流程

class ParallelScheduler:
    async def execute(self, tc_list: list[TCIR], config: SchedulerConfig) -> Report:
        # 1. 构建依赖图
        dag = self.analyzer.build_dag(tc_list)
        
        # 2. 划分执行批次
        batches = self.analyzer.generate_batches(dag)
        
        # 3. 初始化资源池
        browser_pool = BrowserPool(max_instances=config.max_browsers)
        worker_pool = WorkerPool(size=config.workers, browser_pool=browser_pool)
        
        # 4. 逐批次执行
        results = []
        for batch in batches:
            batch_results = await self._execute_batch(batch, worker_pool)
            results.extend(batch_results)
            
            # 检查是否需要中断
            if config.fail_fast and any(r.status == "failed" for r in batch_results):
                break
        
        # 5. 聚合结果
        return self.aggregator.aggregate(results)
    
    async def _execute_batch(self, batch: Batch, worker_pool: WorkerPool) -> list:
        tasks = []
        for tc_id in batch.tasks:
            worker = self.load_balancer.select_worker(tc_id)
            task = asyncio.create_task(worker.execute(tc_id))
            tasks.append(task)
        
        return await asyncio.gather(*tasks, return_exceptions=True)

6.2 失败处理策略

| 策略 | 描述 |
|------|------|
| fail_fast | 首个失败立即终止全部 |
| continue_on_error | 失败后继续执行其他用例 |
| retry_failed | 失败用例自动重试 N 次 |
| skip_dependents | 失败后跳过所有依赖该用例的后续用例 |

配置示例：

scheduler:

  max_browsers: 10
  strategy: "least_connections"
  
  failure_policy:

    max_retries: 2
    retry_delay_ms: 1000
