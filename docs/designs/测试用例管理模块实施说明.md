# 测试用例管理模块实施说明

## 1. 目标与范围
- 目标：在不改动当前线上行为的前提下，先冻结测试用例管理模块的目标契约，并用自动化测试固化。
- 范围：文档与测试先行；运行时代码、数据库迁移、接口实现改造不在本轮。
- 兼容策略：保留 `/api/v1/test-cases`，旧字段不删除，新字段可选。

## 2. 生命周期模型（目标契约）

### 2.1 状态集合
- `draft`
- `review`
- `active`
- `frozen`
- `disabled`
- `archived`

### 2.2 状态语义
- `draft`：草稿态，可编辑，不参与正式执行编排。
- `review`：评审态，等待用例质量审核。
- `active`：启用态，可被执行调度。
- `frozen`：冻结态，内容只读，执行行为可按策略允许/禁止。
- `disabled`：停用态，不参与日常执行。
- `archived`：归档态，终态，不可回退。

### 2.3 合法流转矩阵

| from \\ to | draft | review | active | frozen | disabled | archived |
|---|---:|---:|---:|---:|---:|---:|
| draft | - | Y | - | - | - | Y |
| review | Y | - | Y | - | - | Y |
| active | - | - | - | Y | Y | Y |
| frozen | - | - | Y | - | Y | Y |
| disabled | - | Y | - | - | - | Y |
| archived | - | - | - | - | - | - |

### 2.4 状态流转错误码草案
- `TC_STATE_INVALID`：非法状态值
- `TC_STATE_TRANSITION_DENIED`：不允许的状态流转
- `TC_ARCHIVED_IMMUTABLE`：归档态禁止修改

## 3. 接口兼容策略（目标）

### 3.1 查询参数
- 保留：`page`, `page_size`, `status`, `mode`, `tag`
- 新增可选：`priority`, `keyword`, `updated_from`, `updated_to`, `owner`

### 3.2 响应字段
- 保留既有字段：`id`, `name`, `description`, `mode`, `priority`, `status`, `steps`, `tags`, `created_at`, `updated_at`
- 新增可选字段（向后兼容）：`lifecycle_state`, `last_execution_summary`, `owner`, `updated_by`

### 3.3 兼容规则
- 旧客户端不传新字段、不认新字段，仍可正常使用。
- 新字段全部默认可缺省，服务端不得要求必填。
- 旧调用路径和方法保持不变。

## 4. 查询与筛选扩展草案
- `status`：生命周期状态过滤。
- `mode`：`UI/API/HYBRID` 过滤。
- `tag`：标签包含过滤。
- `priority`：`P0/P1/P2/P3` 过滤。
- `keyword`：名称/描述关键词匹配。
- `updated_from` + `updated_to`：更新时间区间过滤。
- `owner`：负责人过滤。

## 5. 指标与验收门槛
- 契约完整性：状态集合、流转矩阵、兼容规则文档齐全。
- 测试覆盖：
  - 生命周期契约：100% 覆盖全部状态与流转边界。
  - API 契约：覆盖旧参数、扩展参数、旧响应兼容。
  - 回归兼容：现有前端调用路径 smoke 通过。
- 质量门禁：CI 中可见独立 `test-cases-contract` job。

## 6. 实施阶段
- M1：冻结状态机与兼容契约，完成评审。
- M2：落测试骨架（允许先红后绿），CI 挂载 allow-failure。
- M3：稳定后转强制门禁，进入代码实现阶段。
