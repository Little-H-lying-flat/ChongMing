1. 系统概述 (System Overview)

1.1 定义与愿景

缺陷分析智能体 (Defect Analyzer Agent) 是重明架构中负责 "诊" (Diagnose) 和 "愈" (Heal) 的核心组件。它像一位资深的测试专家，不仅能发现问题，还能深入分析根因、评估影响、提供修复建议。

其核心设计哲学是 "Root-Cause-Driven, Knowledge-Accumulated" (根因驱动，知识沉淀)：
- 根因分析：AI 推理缺陷的根本原因（代码/设计/需求/环境）
- 影响评估：分析缺陷影响的模块范围
- 智能关联：基于向量检索匹配历史相似缺陷
- 知识沉淀：修复后的经验自动入库

1.2 核心职责
- 根因分析 (Root Cause Analysis)：推理缺陷产生的根本原因
- 影响范围评估 (Impact Assessment)：分析受影响的模块和功能
- 修复建议 (Fix Suggestion)：提供具体的修复方案
- 相似缺陷匹配 (Similar Defect Matching)：基于 Milvus 检索历史缺陷
- 预防措施 (Prevention Measures)：提供预防类似问题的建议
- 缺陷关联 (Defect Correlation)：自动关联测试失败与已知缺陷

3. 上下文收集层 (Context Collector)

3.1 收集信息类型

| 信息类型 | 内容 | 来源 |
|---------|------|------|
| 失败信息 | 错误消息、堆栈跟踪 | 测试执行器 |
| 执行轨迹 | 操作步骤、截图、网络请求 | Trace Log |
| 代码上下文 | 相关源代码片段 | Git 仓库 |
| 环境信息 | 浏览器版本、系统配置 | 执行环境 |
| 历史记录 | 该用例历史通过/失败记录 | 报告数据库 |

3.2 上下文组装

class ContextCollector:
    async def collect(self, failure: TestFailure) -> DefectContext:
        # 1. 基础失败信息
        basic_info = {
            "test_case_id": failure.tc_id,
            "test_case_name": failure.tc_name,
            "error_message": failure.error,
            "stack_trace": failure.stack_trace,
            "failed_step": failure.step_index,
            "timestamp": failure.timestamp
        }
        
        # 2. 执行轨迹
        trace = await self.trace_store.get(failure.execution_id)
        
        # 3. 相关代码上下文 (如果可用)
        code_context = None
        if failure.source_file:
            code_context = await self.code_fetcher.get_context(
                file=failure.source_file,
                line=failure.line_number,
                context_lines=20
            )
        
        # 4. 历史记录
        history = await self.history_store.get_recent(
            tc_id=failure.tc_id, 
            limit=10
        )
        
        # 5. 环境信息
        env_info = failure.environment
        
        return DefectContext(
            basic_info=basic_info,
            trace=trace,
            code_context=code_context,
            history=history,
            environment=env_info
        )

4. 根因分析层 (Root Cause Analyzer)

4.1 缺陷分类体系

根因类型 (Root Cause Categories):

├── 代码缺陷 (Code Defect)
│   ├── 逻辑错误 (Logic Error)
│   ├── 边界处理 (Boundary Handling)
│   ├── 空指针 (Null Reference)
│   ├── 并发问题 (Concurrency Issue)
│   └── 资源泄露 (Resource Leak)
│
├── 设计缺陷 (Design Defect)
│   ├── 接口设计不合理 (Poor Interface Design)
│   ├── 状态管理问题 (State Management)
│   └── 耦合过紧 (Tight Coupling)
│
├── 需求缺陷 (Requirement Defect)
│   ├── 需求不明确 (Ambiguous Requirement)
│   ├── 需求遗漏 (Missing Requirement)
│   └── 需求冲突 (Conflicting Requirements)
│
├── 环境问题 (Environment Issue)
│   ├── 配置错误 (Configuration Error)
│   ├── 网络问题 (Network Issue)
│   ├── 依赖服务异常 (Dependency Failure)
│   └── 资源不足 (Resource Exhaustion)
│
└── 测试问题 (Test Issue)
    ├── 测试数据问题 (Test Data Issue)
    ├── 测试脚本错误 (Test Script Error)
    └── 时序问题 (Timing Issue)

5. 影响范围评估 (Impact Assessment)

5.1 影响维度

| 维度 | 说明 | 评估方法 |
|------|------|---------|
| 功能影响 | 受影响的功能模块 | 分析用例覆盖的业务功能 |
| 用户影响 | 受影响的用户群体 | 分析功能的用户使用频率 |
| 依赖影响 | 依赖该功能的其他模块 | 分析用例依赖图 |
| 业务影响 | 对业务流程的影响程度 | 结合业务优先级评估 |

5.2 影响评估器

class ImpactAssessor:
    async def assess(self, root_cause: RootCauseReport, 
                     context: DefectContext) -> ImpactReport:
        # 1. 分析受影响的功能模块
        affected_modules = await self._analyze_modules(context)
        
        # 2. 分析依赖关系
        dependent_cases = await self._find_dependents(context.basic_info['test_case_id'])
        
        # 3. 评估业务影响
        business_impact = await self._assess_business_impact(
            modules=affected_modules,
            root_cause=root_cause
        )
        
        return ImpactReport(
            affected_modules=affected_modules,
            dependent_test_cases=dependent_cases,
            user_impact=self._estimate_user_impact(affected_modules),
            business_impact=business_impact,
            severity=self._calculate_severity(business_impact)
        )

6. 相似缺陷匹配 (Similar Defect Matching)

6.1 基于 Milvus 的向量检索

class SimilarDefectMatcher:
    def __init__(self):
        self.milvus = MilvusClient(host="localhost", port=19530)
        self.collection = "defect_knowledge"
        self.embedding_model = "text-embedding-3-small"
    
    async def find_similar(self, context: DefectContext, top_k: int = 5) -> list:
        # 1. 构建查询文本
        query_text = f"""
        错误类型: {context.basic_info['error_message'][:200]}
        失败步骤: {context.trace[-1] if context.trace else ''}
        """
        
        # 2. 向量化
        query_vector = self.embedding_model.encode(query_text)
        
        # 3. Milvus 检索
        results = self.milvus.search(
            collection_name=self.collection,
            data=[query_vector],
            anns_field="embedding",
            limit=top_k,
            output_fields=["defect_id", "title", "root_cause", "fix_solution"]
        )
        
        return [
            SimilarDefect(
                defect_id=hit.entity.get("defect_id"),
                title=hit.entity.get("title"),
                root_cause=hit.entity.get("root_cause"),
                fix_solution=hit.entity.get("fix_solution"),
                similarity=hit.score
            )
            for hit in results[0]
        ]

8. 缺陷自动关联 (Defect Correlation)

8.1 关联策略

| 策略 | 描述 | 置信度 |
|------|------|--------|
| 精确匹配 | 错误消息完全相同 | 高 |
| 模式匹配 | 错误模式相似 | 中 |
| 向量相似 | 语义相似度 > 0.9 | 中 |
| 时间关联 | 相同时间段内批量失败 | 低 |

8.2 自动关联流程

class DefectCorrelator:
    async def correlate(self, failure: TestFailure) -> CorrelationResult:
        # 1. 精确匹配：查找相同错误消息的已知缺陷
        exact_match = await self.defect_db.find_by_error(failure.error)
        if exact_match:
            return CorrelationResult(
                defect_id=exact_match.id,
                confidence=0.95,
                match_type="exact"
            )
        
        # 2. 向量相似匹配
        similar = await self.similar_matcher.find_similar(failure, top_k=1)
        if similar and similar[0].similarity > 0.9:
            return CorrelationResult(
                defect_id=similar[0].defect_id,
                confidence=similar[0].similarity,
                match_type="semantic"
            )
        
        # 3. 无匹配，创建新缺陷
        return CorrelationResult(
            defect_id=None,
            confidence=0,
            match_type="none",
            suggest_create_new=True
        )

9. 知识沉淀层 (Knowledge Base)

9.1 知识入库流程

缺陷修复完成
       ↓
   提取修复经验
       ↓
   向量化存储到 Milvus
       ↓
   更新缺陷知识库

class DefectKnowledgeBase:
    async def save_resolution(self, defect: Defect, resolution: Resolution):
        # 1. 构建知识文档
        knowledge_doc = {
            "defect_id": defect.id,
            "title": defect.title,
            "error_pattern": defect.error_pattern,
            "root_cause": resolution.root_cause,
            "fix_solution": resolution.fix_steps,
            "prevention": resolution.prevention_measures,
            "resolved_at": datetime.now()
        }
        
        # 2. 向量化
        text = f"{defect.title} {defect.error_pattern} {resolution.root_cause}"
        embedding = self.embedding_model.encode(text)
        knowledge_doc["embedding"] = embedding
        
        # 3. 存入 Milvus
        await self.milvus.insert(
            collection_name="defect_knowledge",
            data=[knowledge_doc]
        )
