1. 系统概述 (System Overview)

1.1 定义与愿景

右瞳引擎 (Right Pupil Engine) 是重明架构中负责 "看" (Perceive) 和 "动" (Act) 的核心组件。它模拟人类测试员的视觉操作模式，通过"看屏幕"而非"读代码"来完成 UI 自动化测试。

其核心设计哲学是 "Visual-First, DOM-Fallback" (视觉主导，结构兜底)：
- 主路径 (90%)：像人一样看屏幕，基于视觉坐标操作（抗前端框架变动）
- 兜底路径 (10%)：在视觉失效时，退化为精简 DOM 结构定位
- 多模态感知：使用 Qwen3-VL-Plus 视觉语言模型理解 SoM 标注图
- 智能等待：多信号融合确保页面稳定后再操作

1.2 核心职责
- 视觉感知 (Visual Perception)：截图 + OmniParser 识别页面元素
- 结构感知 (Structural Perception)：DOM 树剪枝，生成精简 HTML
- 融合决策 (Fusion Decision)：Qwen3-VL-Plus 多模态推理
- 原子执行 (Atomic Execution)：坐标点击 / 选择器点击
- 智能等待 (Smart Wait)：多信号融合页面稳定检测
- 资产生产 (Asset Generation)：生成 AUI-IR 与 Trace Log

3. 智能等待层 (Smart Wait Layer)

3.1 多信号融合策略

class SmartWait:
    async def wait_for_stable(self, page: Page) -> bool:
        detectors = {
            "visual": VisualStabilityDetector(page),    # 截图 Hash 稳定
            "network": NetworkIdleDetector(page),        # 无待处理请求
            "dom": DomMutationDetector(page),            # DOM 变更平静
            "animation": AnimationCompleteDetector(page) # CSS 动画结束
        }
        
        while elapsed < timeout_ms:
            signals = await asyncio.gather(*[d.check() for d in detectors.values()])
            if all(signals):
                return True
            await asyncio.sleep(0.5)
        
        return False

3.2 信号检测机制

| 信号 | 检测方法 | 稳定条件 |
|------|---------|---------|
| 视觉稳定 | 截图 Hash 比对 | 连续 3 帧变化率 < 5% |
| 网络空闲 | 监控 XHR/Fetch | 无待处理请求 |
| DOM 平静 | MutationObserver | 1 秒内无变更 |
| 动画完成 | getAnimations() | 无运行中动画 |

class OmniClient:
    async def parse(self, screenshot_base64: str) -> OmniResult:
        response = await self.client.post(
            f"{self.endpoint}/parse",
            json={"image": screenshot_base64}
        )
        
        return OmniResult(
            som_image=response["annotated_image"],
            labels=[
                ElementLabel(
                    id=item["id"],
                    text=item["text"],
                    bbox=BoundingBox(*item["bbox"]),
                    element_type=item["type"],
                    confidence=item["confidence"]
                )
                for item in response["labels"]
            ]
        )

4.2 结构感知：DOM 剪枝器

class DomTreeSimplifier:
    INTERACTIVE_TAGS = ["button", "input", "a", "select", "textarea"]
    INTERACTIVE_ROLES = ["button", "link", "textbox", "checkbox", "menuitem"]
    
    async def simplify(self, page: Page) -> str:
        raw_html = await page.content()
        tree = BeautifulSoup(raw_html, "lxml")
        
        # 1. 删除不可见元素
        for elem in tree.find_all(style=re.compile("display:\s*none")):
            elem.decompose()
        
        # 2. 仅保留交互元素
        interactive_elements = []
        for elem in tree.find_all(self.INTERACTIVE_TAGS):
            interactive_elements.append(self._extract_element_info(elem))
        
        return self._format_summary(interactive_elements)

5. 融合决策层 (Planner Layer)

5.1 Qwen3-VL-Plus 多模态决策

class VisionPlanner:
    def __init__(self):
        self.model = "qwen3-vl-plus"
    
    async def plan(self, intent: str, som_image: str, labels: list, 
                   simplified_html: str = None) -> AuiIR:
        messages = [
            {
                "role": "system",
                "content": """你是一个 UI 自动化专家。根据用户意图和屏幕截图，输出精确的操作指令。
                
输出 JSON 格式：
{
  "strategy": "visual" | "dom",
  "action": "click" | "input" | "scroll" | ...,
  "target": "som_id:X" | "CSS选择器",
  "coordinates": [x, y],
  "confidence": 0.0-1.0
}"""
            },
            {
                "role": "user",
                "content": [
                    {"type": "image", "image": som_image},
                    {"type": "text", "text": f"用户意图：{intent}\n元素列表：{json.dumps(labels)}"}
                ]
            }
        ]
        
        response = await self.llm.generate(messages)
        return self._parse_response(response)

6. 双路径执行层 (Actuator Layer)

6.1 坐标执行器 (视觉策略)

class CoordinateActuator:
    async def execute(self, page: Page, action: str, coordinates: tuple, value: str = None):
        x, y = self._scale_coordinates(page, coordinates)
        
        if action == "click":
            await page.mouse.click(x, y)
        elif action == "input":
            await page.mouse.click(x, y)
            await page.keyboard.type(value, delay=50)

6.2 选择器执行器 (DOM 策略)

class LocatorActuator:
    async def execute(self, page: Page, action: str, selector: str, value: str = None):
        locator = page.locator(selector)
        await locator.wait_for(state="visible", timeout=5000)
        
        if action == "click":
            await locator.click()
        elif action == "input":
            await locator.fill(value)

8. 异常处理与自愈

| 异常类型 | 处理策略 |
|---------|---------|
| ElementNotFound | 切换到 DOM 模式 |
| AmbiguousElement | 注入 HTML 辅助判断 |
| ClickIntercepted | JS 强制点击 |
| Timeout | 重试或标记失败 |

class SelfHealing:
    async def execute_with_healing(self, page: Page, aui_ir: AuiIR) -> ExecutionResult:
        # 1. 尝试主策略 (视觉)
        try:
            result = await self._execute_primary(page, aui_ir)
            if result.success:
                return result
        except ElementNotFoundError:
            pass
        
        # 2. 切换到兜底策略 (DOM)
        if aui_ir.fallback:
            result = await self._execute_fallback(page, aui_ir)
            result.healed = True
            return result
        
        return ExecutionResult(success=False)

11. 双模态执行机制 (Dual-Mode Execution) 【v2.1 新增】

11.1 概述

双模态执行机制解决了 AI 自动化测试的两个核心痛点:
- 痛点1: 规划太慢 - 每次操作需要 LLM 意图规划，引入 2-5s 延迟
- 痛点2: 定位不准 - 密集 UI (编辑器侧边栏、复杂表格) 识别精度低

11.2 模式定义

┌────────────────┬────────────────────────┬────────────────────────────────┐
│     模式       │       执行流程         │          适用场景              │
├────────────────┼────────────────────────┼────────────────────────────────┤
│ 规划模式       │ 意图 → LLM规划 →       │ • 探索性测试                  │
│ Planning Mode  │ 步骤生成 → 循环执行    │ • 复杂业务流程                │
├────────────────┼────────────────────────┼────────────────────────────────┤
│ 原子模式       │ 动作 → 直接定位 →      │ • 回归测试                    │
│ Atomic Mode    │ 单步执行               │ • 固定业务路径                │
├────────────────┼────────────────────────┼────────────────────────────────┤
│ 深度聚焦       │ 全局 → 区域 →          │ • 密集 UI                     │
│ Deep Focus     │ 元素 三级定位          │ • 编辑器侧边栏/复杂表格       │
└────────────────┴────────────────────────┴────────────────────────────────┘

11.3 原子执行模式 (Atomic Mode)

设计理念: "Instant Actions - 即时操作，零规划延迟"

支持的原子操作:
- atomicTap(target): 点击指定元素
- atomicInput(target, value): 在指定元素输入文本
- atomicHover(target): 悬停在指定元素
- atomicScroll(target, direction): 滚动指定元素
- atomicSelect(target, option): 选择下拉选项
- atomicAssert(target, condition): 断言元素状态

执行流程:
    原子指令 → 跳过规划层 → 直接视觉定位 → 单步执行
                    ↓
             延迟从 3-5s 降至 0.5-1s

11.4 多级视觉聚焦 (Deep Focus)

设计理念: "Deep Think - 深度思考，渐进聚焦"

三级聚焦策略:
    Stage 1: 全局区域识别 (Qwen-VL 分析全屏，输出目标区域边界框)
         ↓
    Stage 2: 区域裁剪检测 (OmniParser 对裁剪区域高精度识别)
         ↓
    Stage 3: 精确目标匹配 (Qwen-VL 从候选元素中精确匹配)

触发条件:
- 元素密度 > 50 个/区域
- 首次定位置信度 < 0.7
- 匹配到多个相似元素
- deepFocus: true 配置指定

11.5 模式路由决策

class ModeRouter:
    ATOMIC_ACTIONS = {"tap", "click", "input", "type", "hover", "scroll", "select"}
    
    def detect_mode(self, tc_ir: dict) -> ExecutionMode:
        # 1. 显式指定优先
        if tc_ir.get("mode") == "atomic":
            return ExecutionMode.ATOMIC
        
        # 2. 根据动作类型推断
        action = tc_ir.get("action", "").lower()
        if action in self.ATOMIC_ACTIONS:
            return ExecutionMode.ATOMIC
        
        # 3. 默认规划模式
        return ExecutionMode.PLANNING
