## 1. 代码风格规范

### 1.1 Python 代码规范

#### 1.1.1 基础规范
- 遵循 **PEP 8** 代码风格
- 使用 **Black** 格式化工具 (line-length=88)
- 使用 **isort** 排序导入
- 使用 **mypy** 进行类型检查

#### 1.1.2 命名规范

| 类型 | 规范 | 示例 |
|------|------|------|
| 模块 | snake_case | `test_executor.py` |
| 类 | PascalCase | `TestCaseGenerator` |
| 函数/方法 | snake_case | `generate_test_case()` |
| 变量 | snake_case | `test_result` |
| 常量 | UPPER_SNAKE | `MAX_RETRIES` |
| 私有成员 | _前缀 | `_internal_state` |

#### 1.1.3 类型注解
```python
# ✅ 推荐
async def execute_test(
    tc_ir: TCIR,
    config: ExecutionConfig | None = None
) -> ExecutionResult:
    ...

# ❌ 不推荐
def execute_test(tc_ir, config=None):
    ...
```

#### 1.1.4 文档字符串
```python
def analyze_defect(
    execution_id: str,
    failure_info: FailureInfo
) -> DefectAnalysisReport:
    """分析测试失败的根本原因。

    Args:

    Returns:
        DefectAnalysisReport: 包含根因分析、影响评估和修复建议

    Raises:
        ExecutionNotFoundError: 当执行记录不存在时
    """
```

#### 1.2.3 组件结构
```tsx
// ✅ 推荐结构
import { useState, useEffect } from 'react';
import { TestCase } from '@/types';
import { fetchTestCases } from '@/api/testCases';
import styles from './TestCaseList.module.css';

interface TestCaseListProps {
  projectId: string;
  onSelect?: (tc: TestCase) => void;
}

export function TestCaseList({ projectId, onSelect }: TestCaseListProps) {
  const [testCases, setTestCases] = useState<TestCase[]>([]);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    loadTestCases();
  }, [projectId]);

  const loadTestCases = async () => {
    setLoading(true);
    const data = await fetchTestCases(projectId);
    setTestCases(data);
    setLoading(false);
  };

  if (loading) return <Spinner />;

  return (
    <ul className={styles.list}>
      {testCases.map(tc => (
        <li key={tc.id} onClick={() => onSelect?.(tc)}>
          {tc.name}
        </li>
      ))}
    </ul>
  );
}
```

## 2. Git 工作流规范

### 2.1 分支策略

```
main                     # 生产分支 (受保护)
├── develop              # 开发主分支
│   ├── feature/*        # 功能分支
│   ├── bugfix/*         # Bug 修复分支
│   └── refactor/*       # 重构分支
├── release/*            # 发布分支
└── hotfix/*             # 紧急修复分支
```

### 2.2 分支命名规范

| 类型 | 格式 | 示例 |
|------|------|------|
| 功能开发 | `feature/{issue-id}-{简短描述}` | `feature/ND-001-prd-parser` |
| Bug 修复 | `bugfix/{issue-id}-{简短描述}` | `bugfix/RP-003-locator-timeout` |
| 热修复 | `hotfix/{版本}-{描述}` | `hotfix/v2.0.1-auth-fix` |
| 发布 | `release/{版本号}` | `release/v2.1.0` |

### 2.3 Commit 规范

使用 **Conventional Commits** 格式：

```
<type>(<scope>): <description>

[optional body]

[optional footer(s)]
```

#### 2.3.1 Type 类型

| Type | 描述 |
|------|------|
| `feat` | 新功能 |
| `fix` | Bug 修复 |
| `docs` | 文档更新 |
| `style` | 代码格式 (不影响逻辑) |
| `refactor` | 重构 (不增加功能/修复bug) |
| `perf` | 性能优化 |
| `test` | 测试相关 |
| `chore` | 构建/工具/依赖 |
| `ci` | CI/CD 配置 |

#### 2.3.2 Scope 范围

| Scope | 描述 |
|-------|------|
| `neural` | 神经设计层 |
| `right-pupil` | 右瞳引擎 |
| `left-pupil` | 左瞳引擎 |
| `turbo` | 涡轮引擎 |
| `phoenix` | 凤凰涅槃层 |
| `defect` | 缺陷分析 |
| `healing` | 自愈中心 |
| `frontend` | 前端 |
| `api` | API 网关 |
| `celery` | 任务调度 |
| `vrt` | 视觉回归 |
| `infra` | 基础设施 |

#### 2.3.3 Commit 示例

```bash
# ✅ 好的 Commit
feat(neural): 实现 PRD 解析器核心逻辑

- 支持 Markdown 格式解析
- 添加模块识别功能
- 集成 LangChain 处理流程

Closes #ND-001

# ✅ 好的 Commit
fix(right-pupil): 修复视觉定位超时问题

将默认超时从 5s 增加到 10s，并添加重试机制

Fixes #RP-003

# ❌ 不好的 Commit
update code
fixed bug
WIP
```

### 2.4 Pull Request 规范

#### 2.4.1 PR 标题
```
[{type}] {scope}: {简短描述} (#{issue-id})
```

示例：`[feat] neural: 实现 PRD 解析器 (#ND-001)`

#### 2.4.2 PR 模板
```markdown
## 变更说明
<!-- 描述这个 PR 做了什么 -->

## 关联 Issue
Closes #{issue-id}

## 变更类型
- [ ] 新功能 (feat)
- [ ] Bug 修复 (fix)
- [ ] 重构 (refactor)
- [ ] 文档 (docs)
- [ ] 其他

## 测试
- [ ] 单元测试通过
- [ ] 集成测试通过
- [ ] 本地验证通过

## 截图/录屏
<!-- 如果是 UI 变更，请附上截图 -->

## Checklist
- [ ] 代码已自测
- [ ] 类型注解完整
- [ ] 文档已更新
- [ ] 无安全风险
```

### 2.5 Code Review 规范

#### 2.5.1 必须检查项
- [ ] 逻辑正确性
- [ ] 边界条件处理
- [ ] 错误处理完善
- [ ] 类型注解完整
- [ ] 单元测试覆盖
- [ ] 无硬编码/魔法数字
- [ ] 日志输出合理
- [ ] 无敏感信息泄露

#### 2.5.2 审核流程
1. 至少 1 个 Approval
2. CI 检查全部通过
3. 无 Merge Conflicts
4. PR 作者不可自行 Merge

## 5. 版本号规范

遵循 **Semantic Versioning 2.0**：

```
MAJOR.MINOR.PATCH
```

| 版本段 | 场景 |
|--------|------|
| MAJOR | 不兼容的 API 变更 |
| MINOR | 向后兼容的功能新增 |
| PATCH | 向后兼容的 Bug 修复 |

示例：`v2.1.3`
